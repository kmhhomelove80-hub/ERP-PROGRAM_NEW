# 기존 주문의 미배정 물량 추가 피킹

## 사용 순서

1. 추가 물량을 실제 입고 완료로 등록합니다. 이미 예정 등록한 물량이면 새 입고 대신 도착 확인합니다.
2. PC의 피킹 주문 이력에서 기존 주문을 찾습니다. 최초 배정분이 모두 출고됐다면 상태 ‘전체’에서도 찾으세요.
3. 주문 상세의 **미배정 물량 추가 피킹**을 누릅니다.
4. 원래 요청·기존 배정/출고·취소 제외 수량과 추가 대상 수량을 확인합니다.
5. 새 입고 위치와 추가 수량을 확인합니다. 입고 완료된 부산(Y09) 가용 재고만 사용합니다.
6. 확인란에 체크합니다. 일부만 확보되었다면 남은 부족을 확인하고 부분 추가 배정에 동의합니다.
7. **기존 주문에 추가 예약 확정**을 누릅니다.
8. 기존 주문 번호의 피킹리스트와 고객 양식에서 결과를 확인하고 필요하면 다시 인쇄합니다. 실제 출고 후 추가 예약 행을 Release합니다.

## 보존되는 기록

새 PickingOrder는 만들지 않습니다. 최초 고객 원본·요청 수량·등록 당시 부족표와 이미 출고한 1차 배정의 완료 정보는 보존합니다. 현재 요청 충족 현황과 두 피킹 인쇄 양식은 추가 예약을 함께 읽습니다. 이 작업은 예약이며 현재고를 차감하지 않습니다.

100개 주문에서 80개를 먼저 예약/출고한 뒤 20개가 입고되면 최대 20개만 같은 주문에 추가합니다. 8개만 먼저 들어오면 8개 추가 후 남은 12개가 입고될 때 다시 진행할 수 있습니다.

## 제한과 보호

- 모든 권한 계정만 사용할 수 있으며 조회 전용은 페이지 접근과 직접 확정 요청도 차단합니다.
- 이미 정상/대체 배정·출고한 수량을 빼고 계산합니다. 취소 물량을 자동으로 다시 예약하지 않으며 기존 배정이 전부 취소된 주문은 추가하지 않습니다.
- 입고 예정분을 추가 예약 대상으로 잡지 않습니다. 기존에 예정분을 예약했다면 도착 확인을 사용합니다.
- 원래 요청 자료가 없는 과거 주문은 추정해 추가 배정하지 않습니다.
- 미리보기는 30분간 유효하고 주문·사용자에 귀속됩니다. 재고 또는 기존 배정이 바뀌면 다시 조회해야 합니다.
- 같은 확정 요청을 재전송해도 중복 예약하지 않습니다. 주문·재고 잠금과 기존 창고 거래 잠금 안에서 예약 및 감사 이력을 함께 저장합니다.
- 기존 주문 이력의 ‘출고 처리 완료’는 기존 배정 행 기준입니다. 고객 요구 전량 충족을 뜻하지 않을 수 있으므로 미배정은 주문 상세에서 확인합니다.
- DB 구조 변경은 없습니다.

## 개발 검증

80 출고+20 추가, 부분 추가 반복, 원본·고객 출력 보존, 중복 요청, 오래된 미리보기, 취소 제외, 대체 배정 제외, 조회 전용 차단 및 감사 실패 시 롤백을 검증합니다. PostgreSQL 병렬 요청 시험은 별도 준비되어 있으며 SQLite 실행에서 제외됩니다.
