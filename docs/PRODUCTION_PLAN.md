# 생산계획 웹 조회

기존 Django ERP에 `/production/` 메뉴를 추가했습니다. EXE를 실행할 필요 없이 ERP에 로그인한 브라우저에서 조회합니다. 운영 서버에는 아직 적용하지 않았습니다.

## 사용

1. 모든 권한 계정으로 로그인하고 **생산계획 → 엑셀 열기 · 열 연결 설정**을 엽니다.
2. XLSX/XLSM 파일을 선택하고 **파일 읽기**를 누릅니다.
3. 시트, 헤더 시작·끝 행, 데이터 시작 행을 확인합니다. 기본은 `선박등기구`, 2~3행, 4행입니다.
4. 범위를 변경했다면 **시트·헤더 변경 후 열 목록 확인**을 먼저 누릅니다.
5. 표 9개 항목과 부품 4개 항목의 연결을 확인합니다. `열별 샘플 보기`에서 처음 2개 데이터 행을 확인할 수 있습니다.
6. **설정 저장 및 공유 자료 적용**을 누릅니다. 적용 전에는 기존 공유 자료가 유지됩니다.

조회 권한 계정은 최신 적용 자료를 검색·정렬·다운로드할 수 있으며 업로드·열 설정 변경은 할 수 없습니다. 설정과 준비 중인 원본 파일은 업로드한 관리자 계정별로 저장합니다. 확정한 조회 자료는 로그인 사용자와 공유합니다.

## 열 변경 대응

- 저장된 물리적 열 위치를 자동 재사용하지 않습니다. 저장한 **헤더 이름**으로 새 파일의 열을 찾습니다.
- 공백·줄바꿈·구두점 차이는 정리하고, 병합 헤더의 상위/하위 이름도 읽습니다.
- 누락되거나 중복된 헤더는 미연결로 표시합니다. 사용자가 직접 열을 선택한 후 적용해야 합니다.
- 원본 샘플의 `생산 잔량 ①`는 P와 Q에 같은 헤더가 있으므로 **P열을 직접 선택**해야 합니다. 다음 파일도 구분할 수 없으면 다시 확인합니다.
- 헤더가 바뀌면 직접 연결한 새 헤더 이름을 저장할 수 있습니다. 빈 헤더를 직접 선택한 경우 다음 파일에서는 다시 확인해야 합니다.
- 생산일정의 병합값 채우기는 사용자가 연결한 열에 적용합니다. 빈 셀을 병합 범위 밖으로 임의 채우지 않습니다.
- 시트·행 범위 변경 및 다른 창에서 업로드한 파일 변경을 확인 없이 적용할 수 없습니다.

## 조회 화면

전체/항목별 다중 단어 AND 검색, 일정 필터, 전체 검색 결과 정렬, 100행 단위 페이지, CSV 저장을 제공합니다. 생산일정의 줄바꿈은 한 줄로 정리하고 생산일정·ERP 코드는 실제 문자열 길이에 맞춰 열 너비를 정합니다. 화면이 좁으면 가로 스크롤을 사용합니다.

전체 표는 가운데 정렬하며 완료·잔량 숫자만 오른쪽 정렬합니다. 행을 선택하면 아래에도 같은 순서의 가로 요약 행과 광원부·반제품·PCB 번호·광원부코드를 표시하므로 한 화면에서 캡처할 수 있습니다. 중복된 기본 정보 목록은 없습니다. Ctrl+F는 검색창, 관리자의 Ctrl+O는 파일/열 설정입니다.

수식·매크로·외부 연결은 실행하지 않으며 수식은 엑셀에 저장된 계산 결과를 사용합니다. 원본은 수정하지 않습니다. 자료는 서버 DB에 저장하므로 기존 DB 백업에 포함됩니다. 관리자별 준비 원본은 다음 업로드 시 교체되며 다운로드 경로로 노출하지 않습니다. 이 기능은 재고·예약·입출고를 변경하지 않습니다.

파일 제한은 10MB, 압축 해제 80MB, 20,000행·256열·총 2백만 셀입니다.

## 개발·서버 반영

기존 실행 환경에서 이 브랜치를 적용한 뒤 다음 명령이 필요합니다. 기존 DB 백업과 서버 반영은 운영 절차를 따릅니다.

```sh
python manage.py migrate
python manage.py collectstatic --noinput
python manage.py check
python manage.py test inventory.test_production --noinput
```

기존 실행 절차로 서버를 재시작한 뒤 `/production/`을 엽니다. 이 변경에는 실제 생산계획·원본 파일·운영 DB·비밀번호가 포함되지 않습니다.

검증: 열 한 칸 이동·열 역순·생산일정 병합·동명 헤더 미연결·수동 설정·설정 저장·시트 변경·오래된 업로드 차단·권한·CSRF·기존 공유 자료 보존을 Django 테스트로 확인합니다. 브라우저 스모크 검증은 임시 DB와 가상 파일로 업로드→설정→적용→조회·검색·정렬·행 선택·CSV·모바일 화면을 확인합니다.

브라우저 검증(Playwright가 설치된 Python 및 Chromium 필요):

```sh
ERP_TEST_PYTHON=/path/to/erp/python ERP_CHROMIUM=/usr/bin/chromium python scripts/smoke_production.py
```

로컬 SQLite 검증 결과: 216개 테스트 중 실행 항목 통과, PostgreSQL 전용 9개 건너뜀. Chromium에서 PC/모바일 가상 자료 시나리오 통과. 운영 PostgreSQL과 실제 서버 배포는 별도 반영이 필요합니다.
