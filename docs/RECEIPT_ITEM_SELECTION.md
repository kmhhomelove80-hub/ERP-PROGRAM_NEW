# 기존 / 신규 품목 입고 등록

## 기존 품목

입고 관리 → 새 입고 등록에서 기본 선택인 **기존 품목**을 사용합니다. 품목·입고 구분·수량·위치를 입력하고 등록합니다. 재고가 0이어도 품목이 등록돼 있으면 선택할 수 있습니다.

## 신규 품목

1. **신규 품목**을 선택합니다.
2. 신규 ERP 코드·품목명/모델명·사양을 입력합니다. 사양은 선택 입력입니다.
3. 입고 완료/예정, 수량, 실제 위치/예정 식별자를 입력합니다.
4. 예정이라면 예정일·발송 담당자도 입력합니다.
5. 확인 후 반영을 누릅니다. 신규 품목과 입고를 함께 저장합니다.
6. 재고 조회에서 코드·사양·수량·위치를 확인합니다. 다음 입고부터 기존 품목으로 선택합니다.

## 보호 규칙

- 같은 ERP 코드가 이미 있으면 신규 등록을 막고 기존 품목 선택을 안내합니다. 대소문자만 다른 코드도 중복으로 봅니다. -와 *는 보존하며 코드를 임의로 바꾸지 않습니다.
- 품목과 입고는 하나의 거래로 저장합니다. 입력 오류·입고 실패가 있으면 신규 품목도 남기지 않습니다.
- 같은 요청 재전송은 품목·입고를 중복 생성하지 않습니다. 다른 내용을 같은 요청번호로 제출하면 거부합니다.
- 기존 품목을 선택한 경우 품목명·사양을 덮어쓰지 않습니다.
- 조회 전용 계정은 등록할 수 없습니다.
- 예정 물량이 도착했을 때는 중복 새 입고 대신 도착 확인을 사용합니다.
- DB 구조 변경은 없습니다. 기존 품목만 선택하던 이전 화면의 요청도 호환합니다.

검증: 신규 입고·예정 및 도착 확인, 기존 입고, 중복 코드·재전송·잘못된 입력·조회 전용 차단, 실패 시 전체 롤백, 실제 브라우저 선택 전환과 저장 후 조회를 확인했습니다. PostgreSQL 병렬 요청 테스트는 별도이며 SQLite에서 제외됩니다.
