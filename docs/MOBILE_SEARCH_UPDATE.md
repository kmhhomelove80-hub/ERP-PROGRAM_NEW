# 모바일 재고 조회 개선 (2026-11-01)

기준: 사용자 제공 6703ac4 소스 ZIP. GitHub에는 푸시하지 않았다.

- 모바일 목록은 ERP 코드·창고/위치·현재고·가용량 한 줄이며 행을 누르면 모델·사양·상태·예약 할당·출하대기와 이동 요청 버튼을 펼친다. 긴 코드는 목록에서 줄임 표시하고 상세에서 전체를 확인한다.
- 이동 요청은 기존 재고 행을 그대로 대상으로 한다. 입고 예정 또는 가용량 0인 항목에는 이동 버튼이 없다. 관리자 승인 전 재고를 바꾸지 않는다.
- 검색창은 외부 키보드형 스캐너 입력과 Enter를 지원한다. 카메라는 브라우저 BarcodeDetector와 카메라 권한이 필요하며, HTTPS 또는 localhost에서만 사용할 수 있다. 지원 브라우저가 아니면 직접 입력/외부 스캐너 안내를 제공한다. iOS 등 모든 기기에서 카메라 인식을 보장하지 않는다.
- 지원 형식 중 QR, Code 128/39, EAN, UPC, ITF, Data Matrix를 사용한다. 라벨 내용은 ERP 코드 또는 위치 텍스트로 검색하며 URL을 열거나 재고를 변경하지 않는다. 기존 자유 검색과 같아 부분 일치하며 여러 재고가 나올 수 있다.
- 카메라 닫기·페이지 이동·백그라운드 전환 시 카메라 트랙을 종료한다. 스캔 내용은 서버의 기존 검색 요청으로 전송된다.

검증: Django 156개 중 151개 통과, PostgreSQL 전용 5개 제외. check 및 makemigrations --check 통과. Chromium 기존 업무 흐름 + 모바일 320/360/390/430/844px + 행 펼침·이동 + 카메라 모의 성공/권한 거부/미지원 검증 통과. 실제 휴대폰 카메라·실물 라벨, PostgreSQL 동시성, Windows 실행은 이번에 검증하지 않았다.

브라우저 검증: `python3 scripts/smoke_browser.py --artifacts /tmp/sunil-updated-browser` (Playwright 설치된 Python 및 Chromium 필요).

이전 GitHub 자동 검사 실패 로그는 확보하지 못했으며 원인/해결 여부는 확인되지 않았다. 현재 업로드본에는 Git 메타데이터가 없고 별도의 ERP-PROGRAM_NEW checkout도 비어 있다. 원격 게시/CI 검증은 별도다.

## 사진 기준 목록 및 카메라 호환 개선

휴대폰 표의 열 순서는 ITEM No. / 잔량(현재고−allocated) / Location / allocated / HULL이다. HULL에는 현재 예약 상태인 호선/프로젝트와 수량만 표시한다. 여러 위치는 행을 구분하며 행 펼침으로 상세와 이동 요청을 사용한다. 좁은 휴대폰에서는 표 영역을 가로 스크롤해 HULL까지 확인한다.

ZXing library 0.21.3(공식 npm SHA512 검증, Apache-2.0 라이선스 동봉)을 정적 파일로 포함했다. 외부 CDN 연결 없이 네이티브 BarcodeDetector 미지원 브라우저에서 QR/바코드 프레임을 해독한다. 네이티브 인식 결과가 없는 프레임도 로컬 디코더로 확인한다. 실시간 촬영은 HTTPS/localhost 및 카메라 권한이 필요하다. 휴대폰에서 HTTP LAN 주소로 접속하면 브라우저가 실시간 카메라를 막을 수 있으며, 이 경우 사진 촬영/이미지 선택 기능을 사용한다. 사진은 브라우저 안에서 해독하며 서버에 업로드하지 않는다.

검증: Django 157개 중 152개 통과, PostgreSQL 전용 5개 제외. 마이그레이션 변경 없음. Chromium 모바일·PC 업무 흐름 및 실제 QR 이미지의 사진 인식 통과. 실시간 카메라 성공/거부와 HTTP 안내는 모의 검증이며 실제 사용자 휴대폰의 촬영은 미검증이다.

## 이동 목록 실시간 필터

재고 조회와 재고 이동 목록 모두 입력 후 300ms 대기로 자동 검색한다. 휴대폰 키보드의 한글 조합 중에도 입력이 300ms 멈추면 현재 텍스트로 검색하며, 상태 선택/검색어 삭제 시에도 결과와 URL을 갱신한다. 입력 변경 시 이전 요청은 취소하고 이전 응답이 최신 결과를 덮지 못하게 한다. 이동 목록의 부분 응답도 기존 로그인/본인 요청 조회 권한을 유지한다. JavaScript를 사용할 수 없는 환경에서는 기존 검색 버튼을 사용할 수 있다.

## ERP 코드 잘림 수정

사용자가 확인한 ERP 코드 길이는 16자리이며 - 및 * 등의 기호를 포함할 수 있다. 모바일 ITEM No. 열은 최소 176px, 고정폭 글꼴, 한 줄 표시로 구성한다. 줄바꿈과 말줄임은 사용하지 않으며 나머지 열은 표 내부 가로 스크롤로 확인한다. 코드를 자르거나 저장 데이터를 변경하지 않는다. 320/360/390/430/844px에서 특수기호 포함 16자리 코드의 잘림과 수량 열 겹침을 검증한다.

휴대폰 IME가 포커스 이탈까지 compositionend를 보내지 않는 경우를 처리한다. 검색 결과 영역만 교체해 입력값·키보드 포커스를 보존한다. 브라우저에서 조합 완료/blur 없이 검색·결과 복원과 포커스 유지를 검증했다. live_stock.js URL에 버전을 넣어 기존 캐시 갱신을 유도했다.

## 휴대폰 헤더 정렬

ITEM No., 잔량, Location, allocated, HULL 헤더를 누르면 오름차순/내림차순이 전환된다. 현재 방향을 화살표로 표시하고 선택한 열을 강조한다. 정렬은 전체 검색 결과에 적용한 뒤 50개씩 페이지를 나눈다. 검색과 페이지 이동 시 정렬 조건을 보존한다. 잔량은 현재고−allocated의 숫자 순서다. HULL은 현재 예약 호선 중 이름순 첫 호선명을 기준으로 정렬한다(예약 없는 항목은 빈 문자열). 조회만 변경하고 재고/예약 데이터는 변경하지 않는다.

검증: 162개 중 157개 통과, PostgreSQL 전용 5개 제외. 모든 열의 양방향 정렬, 전체 결과 숫자 정렬과 페이지 유지, HULL 다중 예약 합계, 잘못된 정렬값 처리, 모바일 헤더 클릭과 검색 후 정렬 유지 브라우저 검증 통과. DB 구조 변경 없음.

## 2026-11-02 제품 스캔 조회 보완

제품 코드 길이를 현장 확인에 따라 16자리로 정정했다. 저장된 코드나 기존 자료를 임의로 자르거나 길이를 강제로 바꾸지 않는다. HTTP에서는 아이콘 클릭 시 사용자 동작 안에서 사진 촬영/선택을 바로 요청한다. 실제 촬영/선택 화면은 휴대폰 OS에 따라 다르며 실시간 getUserMedia 촬영에는 HTTPS와 권한이 필요하다. 권한 거부 시에도 사진 선택 버튼을 사용할 수 있다.

사진은 고해상도와 일반 해상도, 0/90도 회전 및 강화 탐색으로 확인한다. 카메라 영상은 후면·고해상도를 우선 요청하고 기본 API가 없으면 로컬 디코더를 사용한다. 사진·코드는 브라우저에서 해독하며 서버에는 코드 조회 요청만 보낸다.

스캔 성공 시 상태 조건을 초기화하고 ERP 코드 전체 일치(대소문자 무시)로 조회한다. 유사 품목명·사양이나 접두어가 같은 다른 코드를 섞지 않는다. 결과에 인식 코드·위치/상태 항목 수·등록 수량(예정 포함)·allocated·잔량을 표시하며 품목 미등록과 등록됐지만 잔여 재고가 없는 상태를 구분한다. 검색어를 직접 수정하면 일반 부분 검색으로 돌아간다. 정렬·페이지 이동·엑셀 출력에서도 스캔 조회 조건을 유지한다.

검증: 생성된 16자리 QR 및 90도 회전 Code128 라벨 이미지의 로컬 디코딩부터 위치·수량 조회까지 통과. 실제 사용자 라벨 원본과 실제 휴대폰 광학 촬영은 미검증이며 원본 이미지 파일 확보 시 추가 확인이 필요하다.
