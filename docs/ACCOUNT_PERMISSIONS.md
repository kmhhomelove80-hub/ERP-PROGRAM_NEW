# 직원 계정과 권한 설정

## 계정 만들기

1. 모든 권한 계정으로 PC에서 로그인합니다.
2. 상단 **직원 계정** → **사용자 추가**를 선택합니다.
3. 사용자 이름(ID), 비밀번호, 비밀번호 확인을 입력합니다.
4. **모든 권한** 또는 **조회 권한**을 선택하고 저장합니다. 기본값은 조회 권한입니다.
5. 필요하면 직원 이름·이메일을 입력합니다. 비밀번호는 직원별로 다르게 정하고 개인적으로 전달합니다.

## 두 역할

| 역할 | 조회·검색·정렬·조회용 출력 | 등록·수정·삭제/취소·확정 | 이동 요청·승인 | 직원 계정 관리 |
|---|---|---|---|---|
| 모든 권한 | 가능 | 기존 업무 기능 범위에서 가능 | 가능 | 가능(기존 시스템 책임자 계정 변경 제외) |
| 조회 권한 | 가능 | 불가 | 불가 | 불가 |

모든 권한도 거래 원장을 관리자 화면에서 직접 수정하지 않고 기존 입고·Release·취소 등 감사 이력이 남는 업무 절차를 사용합니다. 조회 전용은 모든 직원의 이동 요청·처리 결과도 읽을 수 있습니다. 예전 일반 계정의 ‘본인 이동만 조회/요청’ 방식은 더 이상 사용하지 않습니다.

## 변경·퇴사 처리

직원 목록에서 계정을 열고 권한을 변경합니다. 퇴사하면 활성 체크를 해제하며 기록은 삭제하지 않습니다. 현재 로그인한 본인 계정은 권한 하향·비활성화를 막아 관리자가 잠기는 실수를 방지합니다. 기존 시스템 책임자 권한은 별도로 보존하며 화면에서 새 최상위 권한을 만들지 않습니다. 권한 변경은 다음 요청부터 적용되고 비밀번호 변경은 기존 관리자 비밀번호 변경 기능을 사용합니다.

## 저장과 동시 조회

저장 전 입력 중인 내용은 다른 사람에게 보이지 않습니다. 저장 완료된 거래는 다른 사용자의 다음 조회 시 보입니다. 화면을 그대로 둔 사용자의 데이터가 자동 갱신되는 구조는 아닙니다. 동시 작업·운영 환경은 별도 점검 대상입니다.

## 변경 검증

기존 staff 계정을 전체 역할로, 일반 계정을 조회 전용으로 재사용합니다. DB 마이그레이션은 없습니다. 조회 전용의 모든 변경 경로 직접 요청 차단, 전체 역할의 거래 처리, 직원 추가·권한 변경·비활성화·본인 권한 보호·기존 책임자 보호 및 로그인 세션 중 권한 회수를 테스트합니다. 일반 계정으로 이동 요청을 하던 직원에게는 적용 전에 새 역할 정책을 안내해야 합니다.
