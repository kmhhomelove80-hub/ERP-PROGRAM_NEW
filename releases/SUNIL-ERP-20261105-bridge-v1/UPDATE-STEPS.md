# 수주 연동 수정본 업데이트 순서

명령은 한 단계씩 실행하고 결과를 확인하세요. 처음 받은 ZIP의 `install.bat`은 사용하지 않습니다.

## 1. 압축 해제

새 수정본의 안쪽 폴더를 다음 위치에 놓으세요.

`C:\SUNIL\updates\SUNIL-ERP-20261105-bridge-v1`

그 안에 `Update-Erp.py`, `manifest.json`, `app` 폴더가 바로 있어야 합니다.
현재 정상 ERP를 실행하는 Windows 계정으로 관리자 PowerShell을 여세요. 다른 계정으로 바꾸지 마세요.

## 2. 사전 점검만 먼저 실행

```powershell
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\SUNIL-ERP-20261105-bridge-v1\Update-Erp.py' check
```

이 단계는 ERP를 중지하거나 코드를 교체하거나 DB를 변경하지 않습니다. 점검 로그와 중복 실행 방지 파일은 만듭니다.
`사전 점검 완료`가 나오면 화면을 전달하세요. 오류가 나면 다음 단계로 가지 마세요.
기존 파일이 다르면 강제로 덮어쓰거나 해시 검사를 끄지 마세요.

## 3. 실제 반영

사전 점검 통과 후 직원들의 저장·입고·출고·예약·이동 처리와 수주 전송을 잠시 멈추세요.
Actas 대조 등록 도구도 동시에 실행하지 마세요.

```powershell
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\SUNIL-ERP-20261105-bridge-v1\Update-Erp.py' apply --work-paused
```

도구가 DB 백업·검증 → ERP만 중지 → 최신 백업·데이터 비교값 기록 → 코드 복구본 생성·교체 → 검사 → 기존 방식으로 재시작 → 웹 검사 → 백업·예약 작업 상태 복구 순으로 처리합니다.
PostgreSQL과 Caddy는 유지합니다. 새 DB 구조 변경은 없으며 이미 적용된 변경을 다시 만들지 않습니다.
완료까지 창을 닫지 마세요. `업데이트와 백업 검증 완료` 메시지를 확인하세요.

## 4. 화면 확인

1. 기존 ERP 주소에 접속해 새로고침하세요.
2. 생산계획조회·관리 메뉴·이동 알림·기존 피킹 화면이 유지되는지 확인하세요.
3. 수주관리에서 보내기를 실행해 고객 자료가 자동 입력되는지 확인하세요.
4. `배정 미리보기`까지만 확인하세요. 미리보기는 예약을 만들지 않습니다.
5. 실제 예약·회신은 처리할 업무 자료로 별도 확인하세요. 이번 검사를 위해 임의의 출고·이동·예약을 만들지 마세요.
6. 운영 점검과 기존 업무 화면을 확인한 뒤 업무를 재개하세요.

## 중단 시

오류 화면과 출력된 업데이트 기록 경로를 전달하세요. 반복해서 적용하거나 DB를 과거 백업으로 덮어쓰지 마세요.
자동 복구가 완료됐다는 메시지가 나오면 기존 ERP 접속부터 확인하세요.
정전 등으로 미완료 기록이 남아 복구가 필요한 경우 같은 계정·같은 배포 폴더에서 코드와 예약 작업만 복구합니다.

```powershell
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\SUNIL-ERP-20261105-bridge-v1\Update-Erp.py' recover
```

새 수정본의 원본 해시가 맞지 않거나 복구가 중단되면 기록을 직접 수정하지 말고 결과를 전달하세요.
