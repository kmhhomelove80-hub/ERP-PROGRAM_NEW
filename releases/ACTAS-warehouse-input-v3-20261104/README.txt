Actas 창고 입력 확정 검증 v3 — 2026-11-04

v2 현장 실행에서 Y09 전환이 되지 않았는데 파일 파싱을 통과 상태로 표시했습니다.
수량이 달라 해시가 달라도 창고가 바뀌었다는 증거가 되지 않습니다. v1/v2는 사용 중지합니다.
기존 Y02.xls/Y09.xls/result.json은 원인 분석 기록으로 보관하고 대조 자료로 등록하지 마세요.

이번 v3는 먼저 Y09 코드 입력 확정만 검증합니다.
재고 조회 Ctrl+R, Excel 저장 Ctrl+E, SUNIL ERP 등록은 실행하지 않습니다.
따라서 재고 표가 그대로 남는 것은 정상입니다. 코드와 오른쪽 창고명만 확인합니다.
기존 직접 글자 설정(WM_SETTEXT) 대신 키 입력으로 지우고 Y09를 입력한 뒤
Tab으로 확정하고 Shift+Tab으로 돌아와 코드와 포커스가 유지되는지 검사합니다.
실제 PowerBuilder에서의 동작과 창고명 변경은 이번 현장 검증으로 확인해야 합니다.
창고 코드가 바뀌는 UI 조작이며 읽기 전용 진단 도구와 다릅니다.
장부/실제 재고/예약/입출고/서비스/DB 설정은 변경하지 않고 DB에 직접 연결하지 않습니다.

실행
1. ZIP 안의 actas-warehouse-input-v3 폴더를 C:\SUNIL\updates 에 놓습니다.
2. Actas의 저장창·검색창 등은 취소로 닫고 현재고 현황을 열어 둡니다.
3. Actas와 같은 Windows 계정·권한 수준의 PowerShell에서 실행합니다.

& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\actas-warehouse-input-v3\actas_warehouse_input_v3.py' --probe-warehouse Y09

4. 준비되면 start를 입력합니다.
5. 12초 안에 Actas로 돌아가 창고 코드 칸 안쪽을 클릭한 뒤 키보드·마우스에서 손을 뗍니다.
6. 도구가 입력·Tab 확정·돌아온 코드 읽기를 검사합니다. 실제 창고명 변경은 자동 판정하지 않습니다.
7. Y09 코드와 오른쪽 창고명이 부산 창고로 바뀌었는지 직접 확인합니다.
   조회와 저장은 아직 누르지 마세요. 화면과 생성된 input-probe.json을 담당 개발자에게 전달합니다.
   결과는 runs\실행번호\input-probe.json에 있습니다.

오류가 나면 반복 실행하지 말고 오류 화면과 input-probe.json을 전달합니다.
입력 도중 실패하면 코드가 공란/미완성일 수 있으므로 실제 화면을 확인하고 필요하면 직접 유효한 창고 코드로 복원합니다.
다른 창이 열리거나 포커스 이동이 확인되지 않으면 더 입력하지 않습니다.
자판/프로그램 권한 등의 이유로 전송이 실패해도 보안 설정을 완화하지 않습니다.
실행 중 Windows 잠금·원격 데스크톱 연결 해제·다른 직원의 Actas 조작은 피합니다.

추가 설치/.NET3.5/별도 패키지/DB 암호/비밀키는 필요하지 않습니다.
이 검증본은 일괄 추출 실행을 막았습니다. 입력 확인 후 조회/파일 추출 검증을 별도로 이어갑니다.
입력란 글자 읽기 성공만으로 창고 전환 완료라고 표시하지 않습니다.
기존 소수/음수/공란 원본 보존 처리는 유지되며, 이번 모드에서는 XLS 파일을 만들지 않습니다.
