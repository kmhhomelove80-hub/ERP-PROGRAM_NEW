# 입고 LIST → 선일 ERP 실제 입고 연결 개선

배포: SUNIL-ERP-20261105-receive-v1
기존 통합 v3 / bridge-v1 / inbound-v1 / stocktake-v1에서 적용할 수 있습니다. 기존 재고실사·조정, 정리 판정, 모바일·스크롤, 생산계획 속도 개선과 수주 연동을 유지하는 통합 업데이트입니다. 새 마이그레이션은 없으며, 이전 실사 업데이트를 적용하지 않은 서버에는 기존0014 관리 테이블 추가가 함께 적용됩니다.

## 사용 순서

1. 입고 LIST에서 파일을 불러오고 수량 분할·삭제·최종 비고를 확인합니다.
2. 최종 비고에는 로케이션만 입력합니다. 빈 로케이션이 있으면 전송하지 않습니다.
3. 기존 ERP용 복사 옆의 **입고 화면으로 보내기**를 누릅니다.
4. 선일 ERP의 엑셀 일괄 입고 화면에 아래 5열이 자동으로 입력되고 미리보기가 표시됩니다.

| 순서 | 입고 LIST | 입고 화면 |
|---|---|---|
| 1 | 품목코드 | ERP 코드 |
| 2 | 품목명 | 모델명 |
| 3 | 규격(D열값) | 사양 |
| 4 | 분할·삭제 후 수량 | 입고 수량 |
| 5 | 최종 비고 | 로케이션 |

5. 수량·로케이션·기존 품목 설명 유지 안내를 확인하고 확인 항목을 체크합니다.
6. **전체 행 일괄 입고**를 누르면 해당 행을 Y09 입고 완료 재고에 실제 반영합니다.

전송·미리보기 단계에서는 재고를 변경하지 않습니다. 총수량 열·합계·제목·체크박스는 전달하지 않습니다. 삭제한 행은 제외하며, 같은 품목의 분할 행도 개별 입고 원거래로 보존합니다. 기존 ERP용 복사·엑셀·인쇄는 유지합니다. 회사 Actas ERP를 조작하는 기능이 아닙니다.

## 확인할 사항

- 내장 가상 예제는 실제 입고 화면으로 전송하지 못하도록 차단합니다. 실제 입고 파일을 선택하세요.
- 최종 비고는 메모가 아닌 로케이션입니다. 한 번에 1~1,000행, 선일 ERP 입고 수량은 양의 정수만 허용합니다. 소수·범위 초과는 전송을 차단합니다.
- 이미 등록된 코드의 모델명·사양이 입력 자료와 다르면 안내를 보여주며 기존 품목 정보를 덮어쓰지 않습니다. 신규 코드는 전달한 모델명·사양으로 생성됩니다.
- 기존 입고 예정분에 대한 도착 확인과 이 기능을 동시에 사용하면 중복 물량이 될 수 있습니다. 실제 신규 입고 대상인지 확인하세요.
- 같은 작업 화면에서 같은 파일을 보내거나 입고 버튼을 반복해도 같은 요청번호로 처리해 추가 입고하지 않습니다. 이미 반영한 작업의 내용을 바꿔 다시 등록하려 하면 차단합니다. 새로 파일을 불러오거나 화면을 새로 열면 새 작업이므로, 이미 입고한 파일을 새 작업으로 다시 등록하지 마세요.
- 입고 관리 모두 가능 권한이 필요합니다. 다른 사용자의 전송 자료, 변조·만료 자료와 잘못된 로케이션·수량은 거부합니다.
- 입고 성공 후에는 입고 원거래에서 코드·사양·수량·위치를 확인하고, 필요한 경우 기존 입고 취소 기능을 사용하세요. 실사 되돌리기로 입고를 취소하지 않습니다.
