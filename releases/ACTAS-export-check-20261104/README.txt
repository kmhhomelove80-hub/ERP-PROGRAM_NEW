Actas Y02·Y09 파일 추출 검증본 — 2026-11-04

이 도구는 이전 읽기 전용 진단과 다릅니다.
Actas의 창고 조건을 입력하고 조회(Ctrl+R)·파일 저장(Ctrl+E)을 실제 실행합니다.
SUNIL ERP에 자료를 등록하거나 DB에 직접 연결하지 않습니다.
실제 재고/예약/입출고, 서버 서비스, 로컬 설정, 비밀키는 변경하지 않습니다.
별도 패키지나 .NET3.5 설치 없이 기존 Python3.12 표준 라이브러리로 실행합니다.

아직 무인 자동 수집 완성본이 아닙니다. 조회 완료 표시가 없어 창고별로
담당자의 조회 완료 확인을 받아 저장하는 첫 현장 검증 단계입니다.
실제 Actas에서의 입력/조회/추출 동작은 이 검증으로 확인해야 합니다.

준비
1. ZIP 안의 actas-export-check 폴더를 C:\SUNIL\updates 에 둡니다.
2. 서버 PC의 기존 Windows 계정으로 Actas에 로그인해 현재고 현황을 엽니다.
   Actas의 저장창/검색창/오류창은 직접 취소하여 닫아 둡니다.
3. 품목검색은 비우고 대/중/소 분류 등 조회 조건을 전체로 해 둡니다.
4. 창고 코드 Y01/Y02/Y09가 표시된 칸을 클릭해 선택해 둡니다.
5. Actas와 같은 Windows 계정·권한 수준의 PowerShell에서 실행합니다.
   Actas가 관리자 권한이라면 같은 계정의 관리자 PowerShell을 사용합니다.
   비밀번호나 DB 접속 정보를 입력하지 않습니다.

실행
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\actas-export-check\actas_export_check.py'

6. 준비됐으면 PowerShell에 START를 입력합니다. 그 외에는 Enter로 취소합니다.
7. 도구가 Y02를 입력·재확인하고 Ctrl+R을 보냅니다.
   Actas에서 창고 코드가 Y02로 유지되고 해당 창고 표가 갱신됐는지 직접 확인합니다.
   아직 조회 중이면 기다립니다. 창고명도 해당 창고인지 확인합니다.
8. 확인 후 PowerShell로 돌아와 Y02를 입력합니다.
   도구가 Ctrl+E를 보내 새 실행 폴더에 Y02.xls를 저장합니다.
9. Y09도 같은 순서입니다. 표 갱신·창고 확인 후 PowerShell에 Y09를 입력합니다.
   확인되지 않으면 Enter로 중단합니다. 임의의 시간 경과만으로 완료 처리하지 않습니다.
10. 종료 메시지에 나온 runs\실행번호\result.json을 개발 담당자에게 전달합니다.
   두 XLS도 같은 폴더에 남습니다. 자동 전송하지 않습니다.

실행 중 다른 사람이 Actas를 사용하지 않도록 하고 확인 단계 외에는 키보드/마우스를
조작하지 마세요. Ctrl/Shift/Alt/Windows/Enter를 누른 채 기다리지 마세요.
Windows를 잠그거나 연결 중인 원격 데스크톱을 끊지 마세요.

중단 시
- 오류 화면과 result.json만 먼저 전달하고 같은 작업을 자동 재시도하지 마세요.
- 기존 파일을 재사용/덮어쓰지 않습니다. 한 창고만 성공하면 전체 성공으로 표시하지 않습니다.
- 두 창고의 코드·수량이 같으면 오수집 여부를 확인하도록 중단합니다.
- 새 파일의 작성 핸들이 닫히고 내용이 안정된 것을 확인한 뒤 헤더/정수/중복을 검사합니다.
- 음수 원본 값은 그대로 기록합니다. 과거 샘플과 현재 재고가 같다고 가정하지 않습니다.
- 입력칸이 안 보이거나 창이 바뀌면 좌표를 추정해 클릭하지 않고 중단합니다.
- 보안 프로그램 경고가 나오면 허용/제외 설정 없이 중단합니다.

개발 검사는 실제 Actas 전체 동작의 성공을 대신하지 않습니다.
원본 XLS와 결과 기록은 업무 자료이므로 공개 GitHub에 올리지 마세요.
