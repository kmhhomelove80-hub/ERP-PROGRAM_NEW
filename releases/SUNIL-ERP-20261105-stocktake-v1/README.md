# 재고실사·재고조정 및 전체 화면 개선 업데이트

배포 이름: SUNIL-ERP-20261105-stocktake-v1
대상: 기존 통합 v3, bridge-v1, inbound-v1 설치 서버. 수주 연동·입고 LIST 기능을 함께 유지합니다.

## 변경 내용

- SUPER USER 전용 재고실사 / 재고조정 메뉴. 메뉴·직접 주소·파일·실행 모두 같은 권한을 검사합니다.
- 조사 시작 전에 PICKING·포장 완료 및 대상 거래 중지 확인. 전산 출고까지 완료할 필요는 없습니다.
- 조사 엑셀 다운로드 → 실사수량·사유 입력 → 업로드 → 변경 미리보기 → 검증 백업 → 전체 반영.
- 실사는 로케이션에 남은 수량을 입력합니다. 반영 현재고 = 입력 실사수량 + 전산 출고 전 포장 완료 할당 수량. 현재고15·할당4·실사11이면 변경 없음, 실사10이면 현재고14·할당4·가용10입니다.
- 개별 재고조정은 포장분을 포함한 전산 현재고를 입력합니다. 입고 예정 수량도 개별 조정에서 처리할 수 있습니다. 예약 수량보다 적게 변경할 수 없습니다.
- 기존 14열을 유지하고 식별번호·기준수량·포장 제외수량·회차를 추가합니다. 파일에서 빠진 행과 실사수량 빈칸은 미변경, 0은 해당 기준 수량 없음입니다. 사유는 변경·추가에 필수입니다.
- 동일 양식에 새 행을 넣어 새 위치 재고를 추가할 수 있습니다. 미등록 품목은 모델명·사양 검토 후 별도 승인합니다. 기존 재고와의 중복·충돌은 자동 합산하지 않습니다.
- 반영 직전 전체 DB 백업·체크섬·복원 도구의 파일 읽기 검증을 수행합니다. 실패하면 반영하지 않습니다. Windows에서는 기존 runtime.local.json의 BackupDirectory·PgBin을 읽습니다. 실행 계정·DB 비밀값은 기존 서버 설정을 사용합니다.
- 변경 후 관련 거래가 없으면 건별 수량 되돌리기. 되돌리기 전에도 백업합니다. 이후 입출고·이동·예약·품목 변경이 있으면 차단합니다. 신규 재고를 되돌리면 수량0으로 남기고 품목·기록은 삭제하지 않습니다.
- 정리 리스트는 재고 관리 모두 가능 권한자가 사유 없이 기존 유지 / 일괄 유지 / 판정 취소. 같은 상태는 목록·인쇄에서 제외하고, 관련 변경이 발생하면 재검토합니다. 변경됐다가 원래 수량으로 돌아와도 재검토합니다.
- 예약 출고는 최신 SEQ 우선, 동일 피킹 목록을 묶어 표시. 새 피킹 번호는 등록일 기준으로 기존 SEQ와 함께 최신순 정렬합니다. 필터 결과 2,000행 이하는 전체 표시, 더 큰 결과와 미필터 목록은 스크롤 추가 조회. 전체 선택·필터 결과 전체 처리는 아직 안 불러온 행도 포함합니다. 개별 체크 처리와 총수량을 구분합니다.
- 목록 페이지 번호를 스크롤 추가 조회로 전환. 로고 메뉴와 표 헤더 고정, 표 안에서 세로·가로 스크롤. 큰 결과는 필요한 만큼 추가 조회하고 실패 시 다시 시도할 수 있습니다.
- 모바일은 작은 로고·메뉴 버튼, 펼침 메뉴, 터치 크기 개선. 하단 고정 메뉴를 다시 추가하지 않습니다. 돌아가기 시 최근30분 이내 조회 위치·그대로인 선택을 복원합니다. 검색 조건이 바뀌면 다른 목록으로 취급합니다.
- 인쇄 버튼은 남은 페이지를 끝까지 조회한 후 출력합니다. 아직 전체를 읽지 않은 상태에서 브라우저 인쇄를 하면 부분 목록 대신 안내를 표시합니다. 생산계획의 선택 행 인쇄 등 기존 인쇄 대상은 유지합니다.
- 생산계획은 엑셀의 과도한 서식 객체를 만들지 않고 필요한 값·날짜·병합을 읽습니다. 선택한 시트만 변환하고 업로드 중 처리 상태를 표시합니다. 생산계획 목록도 스크롤로 추가 표시합니다. 실제 첨부 파일 1,503행의 기존·개선 변환 결과 일치를 확인했습니다. 측정한 실행 환경에서는 약4.70초 → 0.61초였습니다. 실제 서버 시간은 환경에 따라 달라집니다.

## 서버 업데이트 절차

1. 기존 실행 계정으로 서버에 로그인합니다. 압축을 풀어 Update-Erp.py와 manifest.json이 바로 보이는 폴더를 `C:\SUNIL\updates\SUNIL-ERP-20261105-stocktake-v1`에 둡니다.
2. 같은 계정의 관리자 PowerShell에서 사전 점검합니다. 이 단계는 서버를 중지하거나 재고를 변경하지 않습니다.

```powershell
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\SUNIL-ERP-20261105-stocktake-v1\Update-Erp.py' check
```

3. 통과하면 직원의 저장·입출고·이동·예약 작업을 잠시 멈추고 실행합니다.

```powershell
& 'C:\SUNIL\ERP\.venv\Scripts\python.exe' 'C:\SUNIL\updates\SUNIL-ERP-20261105-stocktake-v1\Update-Erp.py' apply --work-paused
```

4. 이번 업데이트는 0014_stocktake_and_cleanup 마이그레이션으로 별도 관리 테이블3개를 추가합니다. 기존 재고·예약·계정 수량을 변경하는 마이그레이션은 없습니다. 표준 업데이터가 백업·변경 전후 비교·기동 확인·예약 작업 복원을 수행합니다. 실패하면 기록 폴더를 보존하세요. DB는 자동으로 과거 상태로 덮어쓰지 않습니다.
5. 완료 후 Ctrl+F5로 새로고침하고 SUPER USER와 일반 직원 계정에서 메뉴·권한을 확인합니다. app 폴더를 수동으로 덮어쓰지 마세요.

## 사용자가 확인할 사항

- 피킹·포장은 시스템이 실제 포장 상태를 자동 감지할 수 없습니다. 책임자가 모든 대상 할당 자재의 포장·분리를 확인해야 합니다. 조사 중 대상 입출고·이동·예약·전산 출고를 중지하세요. 시스템은 관련 변경을 발견하면 반영을 막습니다.
- 첫 실사는 소수 품목으로 대상·현재고·할당·실사 기준수량을 확인하세요. 단순 기능 확인을 위해 실제 재고에 가상 수량을 등록하지 마세요.
- 신규 품목 코드·모델명·사양, 빈칸과0의 의미, 개별 조정의 포장 포함 기준을 확인하세요.
- 실제 서버의 백업 경로 공간·접근 권한·PostgreSQL18 PgBin 경로를 확인하세요. 백업 오류가 있으면 우회하지 말고 설정을 바로잡아야 합니다.
- 실사·조정은 이 창고 관리 프로그램의 재고만 변경합니다. 회사 Actas ERP 원본은 변경하지 않습니다. 반영 후 ERP 대조 차이를 검토하세요.
- 실제 휴대폰의 메뉴·체크 선택·표 스크롤과 생산계획 파일 업로드 속도를 확인하세요. 브라우저 자동 검사와 실제 기기의 체감 속도는 다를 수 있습니다.
- 입고 LIST의 실제 Actas 붙여넣기는 현장 최종 확인 대상입니다. 별도 Actas 무인 수집·공휴일 제외 정각 작업·VPN 내부 도메인 설정은 이 배포에서 활성화하지 않습니다.
