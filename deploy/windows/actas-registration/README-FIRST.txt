SUNIL Actas 대조 등록 v1

기존 ERP의 대조 자료 등록 기능을 사용하는 별도 실행 도구입니다.
관리 재고·예약 수량을 변경하거나 DB 스키마를 변경하지 않습니다.
서버에서 첫 실행 확인이 필요합니다.

설치
압축 안 actas-register-v1 폴더를 기존 업데이트 자료 보관 위치에 넣으세요.
기존 SUNIL ERP를 실행하는 Windows 계정에서 사용하세요.
실행 버튼은 SUNIL ERP의 기본 설치 위치를 기준으로 합니다.
웹 SUNIL ERP의 관리 권한 계정으로 로그인합니다. Actas/DB 계정이 아닙니다.
비밀번호는 화면에 표시하거나 파일로 저장하지 않습니다.

기존 검증 자료 등록
1. Register-Existing.cmd를 실행하세요.
2. 방금 성공한 v5 실행 폴더의 result.json을 선택하세요.
3. 같은 폴더에 Y02.xls와 Y09.xls가 있어야 합니다.
4. SUNIL ERP 관리 계정으로 로그인하면 검사를 거쳐 두 창고 자료를 함께 등록합니다.
이 모드에서는 Actas 화면을 조작하거나 재조회하지 않습니다.
완료 시 대조 번호와 상세 화면 경로를 표시합니다.
평소 접속하는 ERP 주소에 표시된 경로를 붙이거나 ERP 대조 이력에서 확인하세요.

이후 수집부터 등록까지 실행
Collect-And-Register.cmd를 실행하세요.
SUNIL ERP 로그인 → start → v5와 동일한 창고/조회 확인 → 두 파일 검사 → 자동 등록 순서입니다.
Actas는 로그인 후 현재고 현황을 열어 두세요. 검색·분류 조건은 전체로 두고 저장창은 닫으세요.
다른 사람이 Actas를 조작하지 않도록 하세요.
각 창고에서:
- ready 입력 후 12초 안에 창고 코드 칸을 클릭하고 손을 떼세요.
- 코드와 오른쪽 창고명을 확인한 뒤 y02 input 또는 y09 input을 입력하세요.
- 다시 12초 안에 Actas 창고 코드 칸을 클릭하고 손을 떼세요.
- 도구가 조회하면 코드·창고명 유지와 새 표의 조회 완료를 확인하세요.
- PowerShell에서 y02 또는 y09를 입력하면 파일을 저장합니다.
Ctrl+R/Ctrl+E는 도구가 보냅니다. 수동으로 누르지 마세요.
Y02는 영주제품창고, Y09는 부산창고인지 확인하세요.
조회 완료를 자동 판독하지 않습니다. 명칭/조회가 맞지 않으면 Enter로 중단하세요.
새 수집 결과는 기존 ERP 데이터 보관 위치의 actas/verified-runs 아래 저장합니다.

등록 결과와 재실행
원본 실행 폴더에 registration.json이 생성됩니다.
대조 번호, ERP 기준 시각, 관리 재고 비교 시각, 일치·차이·누락 건수를 기록합니다.
Y02는 본사 참고 자료이고 Y09는 현재 관리 재고와 비교합니다.
원래 result.json은 수집 단계 기록으로 보존됩니다. 등록 여부는 registration.json을 확인하세요.
오류 또는 결과 기록 실패 시 새로 수집하지 말고 같은 result.json으로 등록을 재확인하세요.
같은 수집 기록은 같은 요청번호를 사용하여 중복 등록하지 않습니다.
DB 등록 후 결과 기록만 실패했어도 기존 대조 번호로 복구합니다.
재실행은 최초 비교 값을 유지합니다. 다른 담당자가 같은 요청을 대신 차지할 수 없습니다.
registration_unconfirmed는 등록 여부 재확인이 필요하다는 뜻입니다.
더 최신 대조가 이미 있으면 과거 자료의 신규 등록을 중단합니다.
예상 밖 오류는 종류만 표시하며 연결 비밀값은 기록하지 않습니다.

지원 수량
현재 운영 대조 저장 구조는 정수형입니다. 음수는 그대로 등록합니다.
소수·공란은 반올림·0 치환·행 누락 없이 전체 등록을 중단하고 원본을 보존합니다.
향후 소수 대조 저장은 별도 업데이트가 필요합니다.

보관
result.json, Y02.xls, Y09.xls, registration.json을 함께 보관하세요.
업데이트 폴더 정리 전 원본 실행 폴더를 별도 보관하세요.
등록 후 registration.json을 전달하면 현장 결과를 확인할 수 있습니다.
